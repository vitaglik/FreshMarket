## HTTP-методы в REST

Метод         Назначение
  ------------- -------------------------------------------------
**GET**       Получить ресурс
**POST**      Создать ресурс
**PUT**       Полностью заменить ресурс
**PATCH**     Частично обновить ресурс
**DELETE**    Удалить ресурс
**HEAD**      Получить только заголовки ответа
**OPTIONS**   Узнать, какие методы поддерживает ресурс
**TRACE**     Диагностика HTTP-запроса (редко используется)
**CONNECT**   Создание туннеля (например, HTTPS через прокси)

На практике чаще всего используются: **GET, POST, PUT, PATCH, DELETE**.

## Разница между REST и RESTful (Full REST)

### Не совсем REST

``` http
POST /user/create
POST /user/delete
POST /user/update
```

Здесь действия зашиты в URL.

### RESTful

``` http
GET    /users
GET    /users/15
POST   /users
PUT    /users/15
PATCH  /users/15
DELETE /users/15
```

Здесь URL описывает **ресурс**, а действие определяется HTTP-методом.

## Что чаще используют сегодня

1.  **REST / RESTful** --- самый распространенный вариант.
2.  **GraphQL** --- современные SPA и мобильные приложения.
3.  **gRPC** --- взаимодействие микросервисов.
4.  **WebSocket** --- приложения реального времени.
5.  **SOAP** --- корпоративные и legacy-системы.

### Что выбрать

-   **RESTful API** --- лучший выбор для большинства веб-проектов
    (Laravel, Symfony, Node.js).
-   **GraphQL** --- если клиентам нужны гибкие запросы и разные наборы
    данных.
-   **gRPC** --- если важны скорость и взаимодействие между
    микросервисами.
-   **WebSocket** --- если требуется обмен данными в реальном времени.
-   **SOAP** --- если интеграция идет с банковскими, государственными
    или старыми корпоративными системами.
